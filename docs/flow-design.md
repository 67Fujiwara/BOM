# BOM → 相見積 → 商社選定 → 正式見積 フロー設計書

- 版：**v4.1**（2026-10-22）。ラウンド3（BLOCKING 3・AMBIGUOUS 21）とラウンド4（AMBIGUOUS 7・文面整合 5）をすべて反映（§16 境界ケース）
- 前提：`docs/keyboard-spec-v0.1.md` を採用し、本書 §14 の差分（v0.2）を上書きする
- 範囲：電気部品のみ

## 0. 目標（変えない）

1. 設計 → 購買 → 商社選定 → 正式見積依頼 までが一直線に流れる
2. 購買からの指摘で設計が直す **コストを限りなくゼロ** にする（資料を作り直さない、転記しない、同じ指摘を二度受けない）
3. 設計・購買・PM の **意思疎通による手戻りをゼロ** にする（誰のボールか・期限・次に押すキーが画面に出ている）

## 1. 共有の前提

- **1案件1ストア、3者同時参照**。保存先は共有ストア（`sync/` の軽量サーバ。無い場合はブラウザ単体で動き、同じ構造の JSON を書き出す）。
- **ログイン**：氏名と役割（設計 / 購買 / PM）。すべてのイベントに `actor` が付く。
- **列単位の書き込み権限**：

| 列 | 書ける役割 |
| --- | --- |
| 設計列（§3.1） | 設計 |
| 商社別の見積列・正式見積列・発注数・追加費用・発注済・入荷済・入荷予定・ロット | 購買 |
| 採用（選定） | 案件設定の「選定者」（既定：設計）。納期NG 対策で PM が **委譲** した行は購買 |
| 案件設定 PM 項目（案件納期・**社内工程日数（この案件）**・予算・重み確定・**選定者**・設計変更の PM 承認要否・上長決裁条件） | 初期値は案件作成者（仮）、確定と変更は PM |
| 案件設定 購買項目（回答期限の既定・見積完了条件・各閾値・通貨・休日・社内工程日数の **プリセット（新規案件の既定値）**・正式見積の所要日数） | 購買（初期値は作成者） |
| 購買の列（見積・正式見積・発注数・追加費用・発注/入荷） | **即時反映**（公開の仕組みは設計列と指摘だけ） |
| 決定（承認・却下・対策区分） | PM |

- 役割外のキーはステータスバーで灰色、パレットでは「権限なし（購買の列）」と出て実行できない。
- **`Ctrl+Z` は自分の操作だけ**戻す。**公開済の値への `Ctrl+Z` は Rev を消さず、逆向きの作業中変更として積む**（ステータスバー「公開済の値を戻します（未公開として積む）」。次の `Ctrl+Enter` で Rev+1）。他人の変更は履歴パネルから「この変更を取り消す」（相手の受信箱に出る）。
- 通知はアプリ内（ランプ・受信箱）。日次ダイジェストは共有サーバの機能（本文は「あなた宛 n 行」のみ）。

## 2. 役割・ボール・受信箱

| 役割 | やること | 既定ビュー |
| --- | --- | --- |
| 設計 | BOM を作る、提出する、指摘に対応/回答する、商社を選ぶ（選定者が設計のとき） | `4` 要確認 |
| 購買 | 提出を受け取る、相見積先を確定、概算見積を依頼・取り込む、指摘を起票、正式見積を依頼・回答を入力、発注・入荷 | `9` 購買作業 |
| PM | 要決定を決める、案件設定 PM 項目を確定、変更セットを承認 | `7` 要決定 |

- 案件に **担当者 3 名**（設計・購買・PM。副担当は任意）を持つ。受信箱・ヘッダーの「○○待ち」は **担当者宛** に数える（担当者が未設定の役割は、その役割の全員に出る）。担当交代は案件設定（PM 項目）。

## 4. 行の状態・フラグ・遷移

```
下書き ─提出(Ctrl+Enter)→ 提出済 → 見積中 → 見積済 → 選定済 → 正式依頼中 → 正式見積済 → 発注済 → 入荷済
取消（提出後の削除。取り消し線で残り集計から除外）／ 置換済（→R0xx）
```

- **状態は上の直列だけ**。戻りは **フラグ** で表す（状態名に括弧書きはしない）：

| フラグ | 付く条件 | 外れる条件 | ボール |
| --- | --- | --- | --- |
| 指摘あり | 未対応の指摘がある | 指摘が確認済/見送り | 種別の R |
| 再見積要 | 変更セットで **正規化後の型式** またはメーカが変わった／概算段階で必要数 ±20% 超または MOQ またぎ／正式依頼中以降は **数量のいかなる変更も** | 購買が `概算見積を依頼`（見積中へ）、または `5`/`9` の行で **`Ctrl+.`** → `1 据え置き（旧見積を有効に戻す）/ 2 再見積`（**行単位**。商社単位は要再確認だけ。`Enter` はどのビューでもセル編集） | 購買 |
| 要再確認 | 指摘対応（**種別を問わず**）による型式/メーカの修正、置換、提案適用（有効な見積がある行だけ） | 購買が `5` で商社ごとに `1 据え置き / 2 再見積 / 3 提案値で確定` | 購買 |
| 表記修正 | 正規化後の型式が同じ（空白・全角半角・大文字小文字・区切り記号の違いだけ） | 購買が `x` 確認 | 購買（見積は有効のまま） |
| 発注数要確認 | 必要数の公開で発注数を再計算したが購買が手で変えていた | 購買が `x` | 購買 |
| 取下げ・再発行対象 | 正式依頼中以降の行で数量・型式・必要日が変わった、案件納期変更で必要日が変わった | `正式見積を依頼` で Rev+1 | 購買 |
| PM承認待ち | 例外選定（閾値超）、変更セット（PM 承認 ON）、先行採用 | PM の `y` / `Shift+Y` | PM |
| 差分超過 | 正式単価が閾値超 | PM の決定 | PM |
| 納期NG | 採用商社の納期（または入荷予定）が必要日を超える | PM が対策区分を割当 | PM → 対策の担当 |
| 先行発注判断 | 見積済で `商社納期 > 必要日 − 正式見積の所要日数` | PM の `y` 許可 / `Shift+Y` | PM |
| 代替承認待ち | 代替可否＝客先承認要 の行で型式またはメーカが変わる **すべての経路**（提案適用・廃番・設計の `r`・同一行編集） | 設計が指摘パネルで回答種別「客先承認取得（番号・日付）」 | 設計 |
| 拮抗 | 一括採用で拮抗行を確定 | 選定者が `x` または選び直し | 選定者 |
| 先行 | PM の先行発注許可 | — | 購買 |

- 型式の **正規化**：空白・全角→半角・大文字化・`-`/`_`/`/`/`.` の除去。正規化後が同じなら見積は有効のまま「表記修正」。
- **見積済の成立**：案件設定（購買項目）`見積完了条件`（全社回答 / n社以上 / 回答期限到達で締め）。期限到達で未回答は辞退扱い。状態「見積中」に `回答 2/3` を併記。見積済になった日時を記録し、選定期限（2営業日）と **納期スコアの基準日** にする（基準日が 5 営業日以上古いときは選定時に警告）。
- **先行発注（LTB）**：PM の決定「先行発注許可」があるときだけ、見積済・選定済 → 発注済 の直接遷移を許す。自動で `7` に載るほか、購買が `Ctrl+K → 先行発注を申請`（理由・金額）で載せられる。
- **発注済以降**は設計列をロック。変えたい場合は「発注後変更依頼」を購買へ起票。
- 提出後の `Shift+Delete` は **取消** 状態（下書きだけ物理削除）。
- 状態遷移ごとに §10 から期限を自動計算（営業日）、`待ち日数` を列に出す。超過は状態セルの色が変わる。

## 5. 提出・公開・変更セット

- **`Ctrl+Enter` = 公開**。役割に関係なく「自分の未公開の行 ＋ 自分の下書き指摘」をまとめて発行し、確認に `行 5 / 指摘 1 を公開` と出す。対象は既定で全部、選択行だけでも可。
- **ゲート**（行）：エラーが残る行は不可、警告は `x` 確認済みなら可、「あとで」が残っていれば不可。
- 公開ごとに **Rev** を採番。直前の Rev が自分のもので購買が未確認なら `1 新しい Rev / 2 直前の Rev に追記` を選べる（小刻みな公開で Rev が増えない）。
- **作業中と公開済の分離**：提出済以降の行を設計が編集すると値は作業中に積まれ、購買には「設計作業中 ●」だけ見える。`正式見積を依頼`・`a`・`Shift+A` の対象から作業中●と承認待ちの行は **自動除外**（実行時に「作業中 5 行 / 承認待ち 3 行を除外」と表示、`Space` で一覧）。含めたいときは購買が行で `Ctrl+.` →「設計に公開を依頼」（質問を自動起票）。
- **指摘の対応済の条件**：「指摘が付いたセルの値が公開で変わった」ときだけ対応済。行の他セルだけ変わった場合は「対応中（指摘セル未変更）」として設計の `4` に残る。意図的に閉じるときは指摘パネルの「直さず回答」。
- **変更セット**：公開する変更に指摘対応でないものが含まれていれば `変更理由`（客先要求 / 設計起因 / 廃番・入手難 / コスト / 納期 / その他）と変更番号（任意）を公開単位で1回だけ聞く。**指摘対応と設計変更が混ざった公開は自動で 2 つの Rev に分割**（指摘対応＝即時、変更セット＝承認が要るなら承認待ち）。分割は **行単位**：指摘セルと他セルの両方が変わった行は変更セット側の Rev に入るが、その行の指摘は公開時点で対応済になる（承認待ちでも購買に見える）。案件設定「設計変更は PM 承認が必要」が ON なら変更セットの行は PM承認待ちで `7` に載り、承認されるまで購買には「承認待ちの変更あり」だけ見える。**却下されたら公開を取り消して作業中に戻す**（Rev は「却下」として履歴に残る）。
- **必要数の公開**で発注数を「新必要数を採用商社の MOQ・入数で丸めた値」に再計算。購買が手で変えていた場合は「発注数要確認」。
- `5 変更あり` の既定は **自分が未確認の差分すべて（Rev 横断、起因列つき）**。Rev で絞るのは `<` `>`（`[` `]` は分類移動のまま）。`x` で確認済（差分から消える）。
- Excel 出力（`Ctrl+E`）は社外・保管用。出力先 `1 社内` / `2 商社向け（価格列なし、依頼商社の列のみ）` / `3 保管用（全列）`。

## 6. 指摘（Issue）

### 6.1 データ
`ID・行ID・セル・種別・本文・提案{型式, メーカ, 商社, 単価, 納期, MOQ}・起票者・起票日時・Rev・状態（下書き / 未対応 / 対応中 / 対応済 / 回答済 / 確認済 / 見送り）・回答（設計、種別：説明 / 客先承認取得{番号, 日付}）・決定（PM）・返信スレッド・差戻し回数・期限`

### 6.2 種別と担当

| 種別 | R | A | 既定期限 | 起票不可の行 |
| --- | --- | --- | --- | --- |
| 型式あいまい | 設計 | — | 1 | 客先指定品 |
| メーカ未記入 | 設計 | — | 1 | — |
| 廃番 | 設計（提案適用） | 価格差 閾値超なら PM | 3 | — |
| 代替提案 | 設計 | 代替可否＝客先承認要 → 代替承認待ち | 3 | 客先指定品・代替不可（**メーカ指定＝任意の行は代替不可でもメーカ提案として起票可**） |
| 最小ロット（丸め） | 購買（発注数を丸める） | 余剰 閾値超なら PM | 2 | — |
| 数量見直し依頼 | 設計（必要数を減らせるか） | — | 2 | — |
| 納期NG（PM の `d` から自動起票） | 設計 | — | 1 | — |
| 質問・その他（購買→設計 / 設計→購買） | **起票者の相手役割** | — | 1 | — |
| 発注後変更依頼 | 購買 | PM | 1 | — |
| コスト超過（正式見積差分から自動） | 設計 | PM | 2 | — |

最小ロットの本文テンプレ：「必要数 X → 丸め数量 Y（余剰 ¥Z）」。起票時期は見積回答の取り込み後（MOQ が判明したとき）。選定前は起票する商社の丸め数量、選定後は発注数を使う。

### 6.3 操作（文脈は 1 つずつ）

| 文脈 | キー | 操作 |
| --- | --- | --- |
| 表（ナビ） | `Shift+I` | 指摘を起票：種別を頭文字（`k` 型式あいまい `m` メーカ未記入 `d` 廃番 `a` 代替提案 `l` 最小ロット `r` 数量見直し依頼 `q` 質問 `h` 発注後変更依頼 `o` その他）→ 本文 → `Enter`。廃番・代替提案は `Tab` で提案欄。`J` で次の行に移って連続起票。**納期NG・コスト超過は PM の決定からだけ自動起票**（手では起票しない） |
| 表（ナビ） | `Ctrl+Enter` | 下書き指摘を発行（§5） |
| 表（ナビ、`4`/`5`） | `F8` / `Shift+F8`（ID・状態の列では `n` / `Shift+N` も） | 次 / 前の問題（並びは種別 → 行。ステータスバー `型式あいまい 2/5`）。ID・状態の列から押すと列はそのまま行だけ移る |

- **置換 `r` / 提案を適用**：元行は「置換済（→R081）」。新行に `置換元`。**提案の商社列に提案値（単価・納期・MOQ）を「提案 I-0xx」出典で書き込み**、旧型式の見積は灰色の履歴。指摘は新行に引き継いで「対応済」。新行は「要再確認」で購買の `5` に出て、**商社ごとに** `1 据え置き / 2 再見積 / 3 提案値で確定`（既定：提案商社＝3、他社＝2）。価格差 ＝ 提案単価 − 旧採用単価 で閾値判定、超なら自動で `7`。
- 同一行の型式/メーカ修正で正規化後が変わり、かつ **指摘対応（種別を問わず。型式あいまい・メーカ未記入は例）** のときも同じ `1`/`2` を `5` で商社ごとに選べる。有効な見積が 1 つも無い行には要再確認を付けない（見積前の修正はそのまま）。旧採用単価が無い行では価格差判定をしない。
- 同じ行に複数の代替提案があるとき、1 つを適用すると他は自動で「見送り（I-0xx を適用）」になり、起票者に通知される。
- 見送りにした指摘は行・セルに「見送り済（理由）」が残り、同種別の再起票時に警告。
- **ルール化**：`対象列 × 判定（必須 / 正規表現（メーカ別可）/ 禁止文字 / マスタ照合 / 重複 / 数量と入数の整合）× 重大度`、`作成者・適用範囲・有効`。全案件への昇格は購買。

## 7. 相見積

- 相見積先の確定は購買。商社マスタ：`取引可 / AVL / 取扱メーカ[] / 種別（商社 / 直販）`。行のメーカから依頼可能な商社を自動で絞る。指定商社・客先指定品の行は **指定先 1 社** にだけ依頼。
- **`Ctrl+K → 概算見積を依頼`**（購買）：パネルで商社と **回答期限（既定＝今日＋購買項目の日数）** を入れる → 商社向け依頼 Excel（依頼No = 案件-商社-Rev、回答期限、行ID・部品名・型式・メーカ・**メーカ指定・代替可否・必要数（＝見積数量の基準）**・単位・必要日・備考 ＋ 回答列：単価・納期・MOQ・在庫区分・見積数量・代替提案（型式/メーカ/単価/納期）・有効期限）。状態を「見積中」に。
- **`Ctrl+K → 見積回答を取り込む`**：依頼No と行ID で突合。突合不能・型式不一致は購買の `4`。**代替提案列が非空の行は指摘「代替提案」の下書きを提案欄付きで自動生成**（代替可否＝不可・客先指定品の行は生成せず「商社提案（対象外）」として履歴のみ。ただしメーカ指定＝任意の行はメーカ提案として生成する）。購買は内容を見て `Ctrl+Enter` で発行するだけ。
- `6 商社別` は商社ごとの入力シート（Excel 複数セル貼り付け可）。有効期限切れは警告ランプ、スコア対象外。

## 8. スコアと選定

### 8.1 計算（0〜100、透明な加重平均）
- 基準数量は **必要数**。商社ごとに `丸め数量_v = 必要数を MOQ_v・入数で切り上げ`、`余剰_v = 丸め数量_v − 必要数`。
- 価格 40：`実質単価_v = 単価_v × 丸め数量_v ÷ 必要数`、`100 × 最安実質単価 / 実質単価_v`。
- 納期 30：`余裕日 = 必要日(行) − (基準日 + 商社納期)`。基準日＝見積済になった日。在庫区分＝在庫 は納期 0。余裕 ≥ 0 で 100、負は 0（案件設定の余裕幅で線形）。
- 実績 20：商社マスタの納期遵守率・不良率（入荷記録から自動集計）。無しは 50（「実績なし」表示）。
- 条件 10：`MOQ_v ≤ 必要数` で 100、超なら `100 × 必要数 / MOQ_v`。
- 未回答・辞退・期限切れは対象外。同点は納期 → 価格。`Space` の内訳に商社ごとの丸め数量・余剰金額を表示。
- 重みの既定は購買マスタのプリセット。案件での上書きは購買。**提出 Rev.1 で案件レベルの要決定「案件設定確定（重み・納期・工程日数・予算・選定者）」が `7` に 1 件載る（提出はブロックしない）**。未確定でも選定は可（既定重みで固定）。確定時に推奨が変わる行があれば影響試算（§9.3）を通す。
- 行単位の重み `w`。選定済の行はスコアをスナップショットで固定。

### 8.2 操作
- `a`（値を打つ列では `Alt+a`。§14.1）= **推奨（最高スコア）で採用**。**見積済のみ有効**。見積中では灰色、ステータスバー `回答 2/3 待ち`。
- `Ctrl+Alt+A` = 最安で採用（スコア無視）。v0.3 で `Alt+A` から移した（`Alt`＋英字は「その英字の 1 キー操作」に統一。§14.1）。
- `Shift+A`（値を打つ列では `Alt+Shift+A`）→ `1`〜`9`。1 位以外は理由必須（`1` 納期 `2` 在庫即納 `3` 実績/品質 `4` 集約 `5` 客先指定 `6` その他）。差が **拮抗閾値（5 点）以内**、または **行金額差（実質単価差 × 必要数）** が例外閾値（¥10,000 かつ 3%）以内 → 選定者の裁量で確定。それ以外 → PM承認待ち。
- 見積中の行に `Shift+A` / `Ctrl+Alt+A` = **先行採用**（理由必須、PM承認待ち＝先行発注判断と同じ）。
- 一括 `未採用を推奨で一括採用`：拮抗行は推奨で確定し **拮抗バッジ** を付けて選定者の `4` に「見直し推奨」。`7` に載せるのは承認要（閾値超）だけ。結果 `採用 45 / 拮抗 15 / 承認要 0 / 見積中スキップ 20`。
- 選定確定時に **発注数** を採用商社の丸め数量で自動設定。
- 拮抗バッジの行は選定済として扱い、正式見積依頼に **含めてよい**（依頼時に「拮抗 n 行を含む」と表示）。バッジは見直し推奨の印で、依頼を止めない。
- 商社集約：`Ctrl+K → 商社を集約` → 1社/2社の総額差・納期差を試算 → `Enter` 適用（理由「集約」、承認要の行はまとめて `7`）。

## 9. 要決定（PM）

### 9.1 種別 × 有効キー × 遷移先（表）

`7` ビューのナビで直接効くのは `y` と `Shift+Y`（PM はどの列も書かないので、どの列でもそのまま効く。§14.1）。行で `Enter` を押すと **決定パネル** が開き、その種別で有効な選択肢だけが並ぶ（文字キー）。無効なキーはステータスバーで灰色。ビュー切替 `1`〜`9` は全ビュー共通で変えない（値を打つ列では `Alt+1`〜`Alt+9`。§14.1）。

発注済の行に `d` が付いたとき：設計列はロックのままなので、設計は指摘パネルの回答に代替候補（型式・メーカ）を書く → 購買が「発注後変更依頼」を起票 → PM が承認 → 購買が元行を **取消**（発注取消）→ 設計が `r` で新行を作る（取消後はロックが外れる）。承認されなければ元の発注のまま「受入」。

- 決定はイベント（種別・決定者・日時・理由・ツール外決裁）として行に残り、`Space` で指摘・相見積と並ぶ。Excel「変更点」シートにも出る。
- **上長決裁（ツール外）**：案件設定 PM 項目 `上長決裁の条件`（行の差額 ≥ ¥X、または案件総額が予算比 +n%）に該当する決定だけ、`y` の後に承認者・日付・決裁書 No. の入力が必須。
- `Shift+Enter`（`7`）はコメント付き決定ではなく **行追加のまま**。コメントは `y`/`Shift+Y` の理由欄。

### 9.2 正式見積
- `Ctrl+K → 正式見積を依頼（社外）`：選定済の行（作業中●・承認待ちは除外）を商社ごとに依頼書（依頼No、発行日・回答期限・必要納期・納入先・支払条件・通貨）。Rev+1 のときは差分シート（旧→新）を自動添付。社外にスコア内訳は載せない（`選定記録を出力（社内）` は別）。
- 回答入力は購買。概算との差が閾値（±10% または **¥10,000** の大きい方）以内なら自動で正式見積済。超過なら `7`。
- 正式依頼中以降の行で数量・型式・必要日が変わったら **取下げ・再発行対象**。`8` に「再発行 n 行」。

### 9.3 案件設定の変更（納期・工程日数・重み）
- `Ctrl+K → 案件設定`。PM 項目は PM、購買項目は購買（§1）。理由必須。
- 確定前に **影響試算**：納期NG になる行 n（状態別）、推奨が変わる行 m、総額差、特急費概算、**行必要日が固定の行 k**、**正式依頼中で必要納期が変わる行 j**。
- 確定時の選択：固定必要日の行 → `1 同じ日数だけ前倒し / 2 据え置き`。推奨が変わる m 行 → 「`7` に再選定提案として載せる」チェック。
- 確定後：相対の行必要日は自動追従。納期NG の行だけ `7`。正式依頼中・正式見積済で必要日が変わった行は **自動で「取下げ・再発行対象（必要納期のみ）」**。結果は `5` に「起因：案件納期変更」で出て設計が確認。

### 14.1 v0.3: 1 キー操作と値の入力（利用者テスト ラウンド 2〜6 の結果）

英字・数字の 1 キー操作と「いきなり文字を打つ＝編集」が同じキーでぶつかり、待ち時間・取り消しで見分ける方式では、打つ速さ・Shift・1 文字の値・数字で始まる型番（`1N4148`・`3M`）で必ず取りこぼしが出た。次の決まった規則にする。

- 表の中で英字・数字・記号（Shift 付きも）が **そのまま 1 キー操作** になるのは、操作のための列（ID・状態）だけ。チェックの列（発注・入荷）は `Enter` で切り替え、打った文字は案内だけ。分類の見出しの行では `[` `]` だけ。行を選んでいないときは数字（ビュー切替）だけで、切り替えたあとも行は選ばない（続けて打った文字がどの行にも入らない。`↓` で表へ）。
- 自分が書けない列では、英字・数字・記号は理由とその操作名・Alt の形（「要確認」は `Alt+4`）を知らせる（打った単語が 1 文字ずつ操作にならないように）。例外: どの列も書かない PM は、数字（ビュー切替）と、`7` の `y` / `Shift+Y` がどの列でもそのまま効く。
- 別のタブの変更でカーソルの行がビューから外れたら、行の選択を外して知らせる（隣の行に黙って移さない。編集中の入力は保存せずに知らせる）。自分の操作（隠す・直して要確認から外れた）なら、同じ位置の次の行へ。
- それ以外の列では、英字・数字は **値の打ち始め**（Excel と同じ）。自分の役割で書けない列の英字は、理由と Alt の使い方（Shift 付きなら `Alt+Shift+…`）を知らせる（コマンドにはしない。打った単語が 1 文字ずつ操作になるのを防ぐ）。
- 記号（`?` `/` `[` `]` `<` `>` など）も同じ。文字を打てるセルでは値の打ち始め（`<5mm`・`[A]CN-12`）、それ以外では 1 キー操作。どの列でも `Alt`＋記号でその操作（`Alt+/` 絞り込み）。ヘルプは `F1` でも開く。macOS で `Option` が作る文字（µ・Ω・°）は入力欄にそのまま入る。
- 打って始めた入力（Excel の入力モード、表示「入力」）は、矢印キーで確定して隣のセルへ（選択の列も打った値・言い換えで確定）。`Enter`・`F2` で始めた編集（編集モード、表示「編集」）では矢印は文字の中を動き、選択の列は ↑↓ で候補を選ぶ。編集中の `F2` で入力と編集を切り替える。
- `F8` は見えている並び（`4` は種別の順）で上から下へ回る。いまのビュー・絞り込みに問題があればその中だけ。カーソルの行を直した・確認済みにして `4` の後ろへ動いた（ビューから外れた）ときは、先頭へ戻らずに BOM の並びでその行の次の問題へ。行の選択を外したあと（直してビューから外れた・別のタブの変更）の → ← Tab Home は行を選ばず、`↓` で外したところの続きの行へ。
- 理由・氏名の欄もあるダイアログでは、数字は選択肢を選ぶだけで、確定は `Enter`。
- `Enter` で始めた数値・日付・選択の編集は値を全選択して始める（打ち直しが上書きになる）。文字の列はカーソルを末尾に置く。
- `Alt` を押したまま `Alt`＋英字の操作を続けている間は、`Alt+↑↓` を行の移動にせず `↑↓` として扱う。割り当ての無い `Alt`＋英字はブラウザの既定動作を止めて知らせる。
- **どの列でも `Alt` を押しながら** なら 1 キー操作（`Alt+x`・`Alt+a`・`Alt+Shift+I`・`Alt+4`）。最安で採用は `Ctrl+Alt+A`。次の問題・前の問題は `F8` / `Shift+F8` でも。
- ステータスバーのヒント・通知・サイドバーのビュー番号・`Ctrl+K` と `?` の一覧のキーは、カーソルの列に合わせて Alt 付き・F8 で案内する。
