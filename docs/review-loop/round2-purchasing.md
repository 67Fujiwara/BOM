## 2. 新規 BLOCKING（v2 の画面・キーで6シナリオを歩いて見つけた手戻り）

### NB-01 `7` ビュー内のビュー切替 `Ctrl+1`〜`Ctrl+9` はブラウザ予約キー
- **シナリオ**：S3、S4、S6（PM が `7` で決めた後に `8` 正式見積や `9` に移る）
- **何が起きるか**：Chrome/Edge/Firefox で `Ctrl+1`〜`8` はタブ切替、`Ctrl+9` は最終タブ。keyboard-spec §2-6「ブラウザ予約キーは使わない」に反し、PM は `7` から出るのにマウスが要る（受け入れ基準「マウスに触らず完了」が落ちる）。PM が別タブに飛んで戻ってくる間に承認を押し忘れる。
- **修正案**：`1`〜`9` は全ビューでビュー切替に固定。PM の対策選択は **行で `Enter` → 決定パネル**（Shift+A と同じモーダル）を開き、その中で `1`〜`7` と `y`/`Shift+Y`。パネルの外では `y`/`Shift+Y` だけ直接効く。§9 の表と §13 の `2`〜`7` 行を差し替える。

### NB-02 「見積済（選定待ち）」の行に**ボールが無い**
- **シナリオ**：S3
- **何が起きるか**：§2 ボール表に状態「見積済」が無い（設計：下書き/指摘/再見積要(設計)/代替依頼、購買：提出済/見積中/再見積要/選定済/…、PM：…）。見積済になった瞬間、行は誰の受信箱にも「設計待ち n」にも出ない。選定者（既定 設計）の既定ビュー `4` は指摘・チェックNG のみ。結果「見積済から2営業日」の期限を誰も見ずに超過し、購買が設計に「選んでください」と言いに行く。
- **修正案**：ボール表に **「見積済 → 選定者（案件設定、既定 設計）」** を追加。`4` 要確認の設計フィルタに「選定待ち n 行」を含め、ヘッダー「設計待ち」の内訳に出す。受信箱の `Enter` ジャンプ対象にも入れる。

### NB-03 `Shift+X` が購買にとって「差戻し」と「見送り」の両方
- **シナリオ**：S2（設計が `Shift+Enter` で「直さず回答」した指摘を購買が処理する）
- **何が起きるか**：§6.3/§13 で `Shift+X` ＝「差戻し（購買）/ 見送り（起票者・PM）」。購買は起票者でもあるので、回答済の指摘で `Shift+X` を押したとき「回答を受け入れて見送る（閉じる）」のか「回答を拒否して差し戻す」のか、正反対の結果が同じキーに割り当たっている。押し間違いは設計に二度目の対応を強いる。
- **修正案**：`x` ＝ 確認済（直した場合）/ 見送り（回答済の場合。理由は設計の回答を引用、追記可）。`Shift+X` ＝ 差戻しのみ。PM の見送りは `7` の `Shift+Y`。ステータスバーに「x 回答を受け入れて見送り」「Shift+X 差戻し」と文脈表示。

### NB-04 置換時に購買の提案値が新行に転記されず、据え置き/再見積が商社単位で選べない（B-08 の残り）
- **シナリオ**：S2（廃番2件）
- **何が起きるか**：§1 判定表 B-08 のとおり。提案商社の単価は指摘の提案欄に、新行の商社列には旧型式の値が「要再確認」で入る。購買が `1` 据え置きを押すと旧型式の価格が残り、`2` を押すと提案商社にも再見積を出すことになる。どちらも誤り、正解は手打ち＝転記。
- **修正案**：「提案を適用して置換」で新行の **提案商社の列に提案値（単価・納期・MOQ）を自動記入し「提案値」バッジ**。`5` の確認は商社ごとに `1` 据え置き / `2` 再見積 / `3` 提案値で確定 を選べる（既定：提案商社＝3、他社＝2）。

### NB-05 同一行の型式マイナー修正でも無条件に「再見積要」になり、据え置きが選べない
- **シナリオ**：S2（見積取得後に出た型式あいまい指摘：前後空白・全角半角・サフィックス表記）、S5
- **何が起きるか**：§4「型式・メーカが変わったときだけ状態が提出済（再見積要）に戻り、既存見積は灰色」。`Ctrl+.` の「前後の空白を削除」や「全角→半角」の修正でも再見積要になり、3社の見積が灰色になる。§6.3 の「`1` 再見積不要 / `2` 再見積する」は**置換（`r`）のときだけ**に書かれていて、同一行編集には無い。購買は3社に「型式表記が変わっただけ、価格据え置きで」と連絡するか、灰色の値を手で入れ直す。
- **修正案**：再見積要の判定を「**正規化後の型式**（空白・全角半角・大文字小文字・区切り記号を除去）が変わったとき」にする。正規化後が同じなら見積はそのまま有効で、`5` に「表記修正（見積据え置き）」として出るだけ。正規化後が変わった同一行編集でも、置換と同じ `1`/`2`（商社単位）を `5` で選べるようにする。

### NB-06 「設計作業中●」「承認待ちの変更あり」の行に正式見積依頼・選定ができてしまう
- **シナリオ**：S5（型式5行が作業中または PM 承認待ちの間に、購買が選定済の行をまとめて正式依頼）
- **何が起きるか**：§4 の「PM承認待ちの間は選定・依頼をブロック」は行フラグ（例外選定）に対して書かれており、§5 の変更セットは「承認待ちの変更あり」とだけ見える。購買には値が見えないので、その行を含めて `正式見積を依頼` を出す → 承認・公開された瞬間に「選定済（再見積要）」「取下げ」→ 依頼書 Rev+1 を商社に再送（社外に対する二度手間）。
- **修正案**：`正式見積を依頼` と `a`/`Shift+A` の対象から「作業中●」「承認待ちの変更あり」の行を**自動除外**し、実行時に「作業中 5 行 / 承認待ち 3 行を除外しました（`Space` で一覧）」と出す。含めたい場合は行で `Ctrl+.` →「設計に公開を依頼（質問を自動起票）」。

### NB-07 案件設定が「PM のみ」で、購買の業務項目（回答期限・見積完了条件・閾値・通貨・休日）まで PM 待ちになる
- **シナリオ**：S1（概算見積依頼を出す初日）
- **何が起きるか**：§9.2「`Ctrl+K → 案件設定`（PM のみ、理由必須）」。しかし見積完了条件の「回答期限到達で締め」の回答期限、差分閾値、例外閾値、通貨、休日カレンダー、社内工程日数は案件設定にしか無く、`概算見積を依頼` コマンドに回答期限の入力が無い。PM が設定するまで購買は依頼書に回答期限を書けず、締めも動かない。「誰が決めるか不明で止まる」。
- **修正案**：案件設定を **PM 項目**（案件納期・予算・重み確定・設計変更の PM 承認要否）と **購買項目**（回答期限の既定、見積完了条件、差分/例外/拮抗閾値、通貨、休日カレンダー、社内工程日数の既定）に分け、§1 の権限表に「案件設定（購買項目）：購買」を追加。`概算見積を依頼` のパネルで **回答期限を依頼ごとに入力**（既定＝今日＋購買項目の日数）し、依頼 Excel のヘッダに出す。

### NB-08 見積回答の「代替提案」列が取り込み後に指摘へ自動変換されず、購買が転記する
- **シナリオ**：S3（3社の回答に代替提案が合計6件）
- **何が起きるか**：§7 の回答列に「代替提案」があるが、取り込み後の扱いは「突合不能・型式不一致は要確認（購買）」だけ。商社の提案を設計に渡すには購買が `Shift+I` → `a` → 型式・メーカ・商社・単価・納期を**手で打ち直す**。
- **修正案**：取り込み時に代替提案列が非空の行は **指摘「代替提案」の下書きを提案欄付きで自動生成**（提案商社＝回答商社、単価・納期・MOQ は回答値）。購買は `4` の購買フィルタで内容を見て `Ctrl+Enter` で発行するだけ。代替可否＝不可 / 客先指定品の行は自動生成せず「商社提案（対象外）」として履歴だけ残す。

### NB-09 調達区分「指定商社」「客先指定品」に、指定先を書く列が無い
- **シナリオ**：S1
- **何が起きるか**：§3.1「指定商社は1社のみに依頼」とあるが、設計の列に **指定商社名** が無い。客先指定品も指定メーカ・承認番号を書く場所が無い（備考に書くと取り込み・自動絞り込みが効かない）。購買は行ごとに「どこに？」と聞き直す。提出前チェック（§12）でも検出できない。
- **修正案**：設計の列に `指定先`（調達区分が指定商社なら商社マスタから選択、客先指定品なら指定メーカ＋客先承認番号/図書番号）を追加し、調達区分が指定系のとき必須（エラー）。`概算見積を依頼` はこの列で自動的に1社に絞る。

### NB-10 依頼 Excel に「代替可否」「メーカ指定」が無く、商社に伝わらない
- **シナリオ**：S1、S3
- **何が起きるか**：§7 の依頼列は 行ID・部品名・型式・メーカ・数量・単位・必要日・備考。商社は「同等品可」の行に提案せず、「不可」の行に提案してくる。購買が備考に「同等品可」を行ごとに書き足す＝転記。また「数量」が必要数か発注数かが書かれていない（MOQ は回答で初めて分かるので必要数であるべき）。
- **修正案**：依頼列に `代替可否`・`メーカ指定`・`必要数（見積数量）` を追加し、「数量＝必要数」と明記。回答側の「見積数量」は商社が MOQ で丸めた数量。

### NB-11 案件納期の変更で、正式依頼中の依頼書（必要納期）の再発行がマークされない
- **シナリオ**：S6
- **何が起きるか**：§9.2 は「必要日を過ぎる行だけ納期NG で `7`」。新納期に間に合う行でも、正式依頼中の依頼書には**旧必要納期**が書かれており、商社の回答納期は旧日付に対するもの。§9.1 の「正式依頼中の行が変わったら選定済（再見積要）」は行の値変更が対象で、案件納期の変更は含まれない。購買が気づかなければ商社は旧納期で手配する。
- **修正案**：案件納期（または社内工程日数）の確定時に、正式依頼中・正式見積済で必要日が変わった行を **自動で「依頼書 Rev+1 対象（必要納期のみ変更）」にマーク**し、`8` 正式見積ビューに「再発行 n 行」を出す。`正式見積を依頼` を実行すると差分シート（必要納期の旧→新）だけが付いた Rev+1 を生成。回答納期が新必要日を超えたら納期NG に入る。

## 3. 新規 AMBIGUOUS

### NA-01 案件設定の初期値（予算・社内工程日数・通貨・閾値）を誰がいつ入れるか、「提出時に PM が重みを確定」が提出をブロックするか
- **シナリオ**：S1
- **何が起きるか**：新規 BOM ガイドは案件ID・案件名・納期・購買担当者・希望商社のみ。予算・社内工程日数・通貨は PM 列だが、PM がいつ入れるかの手順が無い。§8.1「提出時に PM が確定（既定のままでも可）」が「PM の操作を待つ」なら設計の提出が止まり、「待たない」なら `7` に何も載らない。
- **修正案**：提出時に「案件設定 未確定」を **PM の `7` に案件レベルで1件**載せる（提出はブロックしない）。PM が `y` で既定を確定、または `Enter` で編集。未確定のままでもスコアは既定重みで計算し、ヘッダーに「重み：既定（未確定）」と出す。

### NA-02 指摘が自動で「対応済」になる条件
- **シナリオ**：S2
- **何が起きるか**：§5「公開した瞬間に、対応中の指摘は自動で対応済」。「対応中」が「指摘のセルが変わった」なのか「行のどこかが変わった」なのか「`n` で飛んで `Enter` した」なのか不明。設計がメーカだけ直して型式あいまいが対応済になれば、購買は差戻し→二度目。
- **修正案**：「指摘が付いたセルの値が公開で変わった」ときだけ対応済。行の他セルだけ変わった場合は「対応中（指摘セル未変更）」として設計の `4` に残す。設計が意図的に閉じたいときは `Shift+Enter` 回答。

### NA-03 「最小ロット」の R＝購買 と PM キー `5`「数量見直し → 指摘『最小ロット』を自動起票」が循環する
- **シナリオ**：S2、S4
- **何が起きるか**：PM が数量見直し（＝設計に必要数を減らせないか聞きたい）を選ぶと、R＝購買の指摘が起票され、ボールは購買のまま設計に届かない。
- **修正案**：種別を「最小ロット（丸め）」R＝購買 と「数量見直し依頼」R＝設計 に分ける。PM `5` は後者を起票。最小ロット指摘の本文テンプレに「必要数 X → 発注数 Y（余剰 ¥Z）、必要数を減らせますか」を自動記入。

### NA-04 `Shift+Y` 却下が「設計のボールへ」固定
- **シナリオ**：S4（選定者＝購買の案件）
- **何が起きるか**：§9「見積済に戻し設計のボールへ」。選定者が購買の案件では誤ルート。
- **修正案**：「選定者のボールへ」に書き換え、ボール表の「見積済 → 選定者」（NB-02）と揃える。

### NA-05 PM `2`「次点商社へ」で次点の概算見積が有効期限切れのとき
- **シナリオ**：S4（正式見積に数週間かかった後）
- **何が起きるか**：§8.1 で期限切れはスコア対象外なので「次点」が存在しない、または3位が次点になる。何が起きるか書かれていない。
- **修正案**：`2` 実行時に次点の見積が期限切れなら「次点（因幡）の概算見積は期限切れ。`1` 再見積してから選定 / `2` 3位（○○）へ」と出す。再見積を選ぶと当該商社だけ再見積要。

### NA-06 正式依頼中の数量変更：§4 の閾値（±20%）と §9.1「変わったら」のどちらか
- **シナリオ**：S5（数量変更3行、うち1行は正式依頼中で +10%）
- **何が起きるか**：§4 では再見積要にならず、§9.1 では「選定済（再見積要）」に戻る。購買は依頼書を取り下げるべきか分からない。
- **修正案**：正式依頼中以降は **数量のいかなる変更も**「取下げ・再発行対象」（商社の正式見積は数量に紐づくため）。概算段階だけ ±20% を適用、と §4 に明記。

### NA-07 公開済の変更を設計が `Ctrl+Z` したとき
- **シナリオ**：S5
- **何が起きるか**：§1「自分の操作だけ戻す」。公開後に `Ctrl+Z` すると Rev が消えるのか、逆方向の未公開変更が積まれるのか不明。購買は公開値で再見積を出し始めている。
- **修正案**：公開後の `Ctrl+Z` は **新しい作業中変更（逆変更）** として積み、Rev と公開値は不変。次の `Ctrl+Enter` で Rev+1 として出る。ステータスバーに「公開済の値を戻します（未公開として積む）」。

### NA-08 案件納期の変更時、行に個別設定された必要日をどう扱うか
- **シナリオ**：S6
- **何が起きるか**：§3.1「空なら案件の必要日を継承」。個別に入れた行（先行手配品など）は前倒しの影響を受けず旧日付のまま残る。影響試算にも出ない。
- **修正案**：影響試算に「行必要日が個別設定の行 n」を出し、確定時に `1` 同じ日数だけ前倒し（既定）/ `2` 据え置き を選ぶ。選んだ結果は `5` 変更ありに「起因：案件納期変更」で出て、設計が確認する。

### NA-09 特急費・送料・分納費の記録先
- **シナリオ**：S6（PM `6` 特急費用承認）
- **何が起きるか**：上限入力はあるが、実際の費用を行に入れる列が無く、ヘッダーの `正式 ¥Y / 予算 ¥Z` に反映されない。
- **修正案**：購買の列に `追加費用`（種別：特急/送料/分納/その他、金額）を追加し、行の金額と案件集計に含める。`6` の上限と実績の差を `7` に出さない（上限内なら完了）。

### NA-10 スコアの条件10・価格40が「発注数」を参照するが、発注数は選定後にしか決まらない
- **シナリオ**：S3
- **何が起きるか**：§3.3「発注数 既定＝必要数、MOQ・入数で丸めた値」。3社の MOQ が違うので、選定前はどの MOQ で丸めるかが無い。§8.1 条件10 `MOQ ≤ 発注数`、価格40「余剰×単価を加算」は発注数を参照しており循環。購買が「なぜこの順位か」を説明できない。
- **修正案**：スコアは **必要数**と商社ごとの `余剰_v = 丸め(必要数, MOQ_v, 入数) − 必要数` で計算。発注数は選定確定時に採用商社の MOQ で確定し、以後は編集可。`Space` の内訳に商社ごとの「丸め後数量・余剰金額」を表示。

### NA-11 先行発注判断を `7` に載せる条件・操作
- **シナリオ**：S6、半導体装置・建築設備の長納期品
- **何が起きるか**：§4「PM の決定イベントがあるときだけ」遷移を許すが、誰がどう `7` に載せるかが無い（指摘種別にも無い）。RACI は R＝購買。
- **修正案**：自動：見積済の時点で `商社納期 > 必要日 − 正式見積の所要日数（購買項目）` の行を「先行発注判断」で `7` へ。手動：購買が行で `Ctrl+K → 先行発注を申請`（理由・金額）。

### NA-12 「代替承認待ち」（代替可否＝客先承認要）のボールと解除
- **シナリオ**：S2（建築設備・自動車の客先承認）
- **何が起きるか**：§6.2 でフラグは付くが、ボール表に無く、客先承認（ツール外）が取れたときに誰がどのキーで外すかが無い。
- **修正案**：ボール＝設計。解除は設計が指摘上で `Shift+Enter` 回答の種別「客先承認取得（承認番号・日付）」。PM の `Shift+Enter`（ツール外決裁の記録）と同じデータ構造に入れる。

### NA-13 「見積対象外」の定義が調達区分ごとに矛盾する
- **シナリオ**：S1
- **何が起きるか**：§3.1「相見積以外は見積対象外（分母から外す）」と「指定商社は1社のみに依頼」が同時に書かれている。客先指定品・支給品の単価を取るのか、ヘッダーの `概算 ¥X` に含むのかが不明。
- **修正案**：調達区分ごとの表を追加：相見積＝複数社・スコア有、指定商社＝1社見積・スコア無・金額に含む、客先指定品＝1社見積（指定先）・金額に含む、支給品/社内在庫＝見積なし・金額に含まない。「分母から外す」は見積済 n/80 の n にだけ適用。

### NA-14 指摘のあるセルで `Shift+Enter` が「直さず回答」になり、keyboard-spec の「下に行を追加」と衝突
- **シナリオ**：S2、S5（指摘のある行の直下に追加行を入れたい）
- **何が起きるか**：§13「`Shift+Enter`（指摘上）＝直さず回答」。指摘セルにカーソルがあると行追加ができない。
- **修正案**：「直さず回答」は `Shift+I` と同じ指摘パネル内の操作（`Space` で開いて `Shift+Enter`）に限定し、表上の `Shift+Enter` は v0.1 どおり行追加のまま。
