## 2. 新規 BLOCKING

### NB1. 案件の PM 担当者・設計担当者が無く、「PM待ち」「設計待ち」が役割宛になる（v2 §2「担当者3名」が v3 で消えた）
- シナリオ：S1 以降すべて（S3 の例外選定、S4 の差分超過、S6 の納期NG が PM のボールになる場面）
- 何が起きるか：v3 §13 のガイドが聞く担当者は購買担当者だけで、§2 にあった「案件に担当者3名（設計・購買・PM）」の記述が無い。受信箱（`Ctrl+P`）の「自分宛」は §2.1 のボール（役割）から数えるので、PM が複数いる組織では **全 PM の受信箱に全案件の要決定が出る**。誰が決めるべき案件かを PM 同士で確認する（聞き直し）か、別の PM が決めてしまう。設計も同じ（設計者が複数いると「設計待ち」が誰のものか分からない）。購買担当者だけ個人に紐づくのは片手落ち。
- 修正案：§2 に「案件に担当者3名（設計・購買・PM、副担当任意）」を復活し、ガイドの手順 6 を「担当者（設計＝作成者、購買、PM）」にする。受信箱の「自分宛」は **役割 かつ 担当者（主または副）** で数え、担当者未設定の案件は受信箱の先頭に「担当者未設定」として出す。ヘッダーの `PM待ち 3` も同じ基準にする。

### NB2. 対策が不成立で戻ってきたとき、行が要決定に戻らず止まる（`d` 代替依頼・`q` 数量見直し・対策区分＝代替品検討）
- シナリオ：S4（差分超過 → `d` 設計へ代替依頼 → 設計「代替なし」）、S6（納期NG → `d` 設計が代替品検討 → 設計「代替なし」）
- 何が起きるか：§9.1 で PM が `d`/`q` を選ぶと差分超過・納期NG のフラグは「PM の決定」で外れ、指摘（コスト超過・数量見直し依頼）または対策区分で設計のボールになる。設計が「直さず回答」で「代替なし」と返すと、指摘は回答済 → 起票者（この場合 PM）のボールになるが、(1) PM の既定ビュー `7` には回答済の指摘が載る種別が無く、PM 向けの `4` も §11 に無い（受信箱から行へ飛ぶしかない）、(2) PM が `x` で回答を受け入れると指摘は見送りになり、行は **正式依頼中・フラグなし・ボール＝購買** に戻る。購買は「+15% のまま、決定が無い」行を前に何をすればよいか分からず PM に聞く。対策区分＝代替品検討（指摘ではなくフラグ）の場合は設計に「できない」と返す操作そのものが無い（質問は購買⇔設計のみで PM 宛が無い）。
- 修正案：(a) 対策起因の指摘（コスト超過・数量見直し依頼）が回答済になったら、**元の要決定種別（差分超過 / 納期NG / 最小ロット）を自動で再掲**し、決定パネルに「代替なし（設計回答）」を表示する。(b) 対策区分の行で担当者（設計/購買）が `Ctrl+.` → 「対策できない（理由）→ PM に戻す」を選べるようにし、納期NG（対策区分なし）に戻す。(c) §11 に PM の `4`（自分が起票者の回答済指摘・委譲した対策の行）を定義するか、`7` に「回答待ち → 回答済」を種別として載せる。

## 3. 新規 AMBIGUOUS

### NA1. 先行発注許可のキーが `y`（§9.1）と `l`（§4 フラグ表・§14 決定パネル）で食い違う
- シナリオ：S6
- 何が起きるか：§9.1 の表では「先行採用 / 先行発注判断：`y` 許可」、§4 の外れる条件は「PM の `l` 許可」、§14 の決定パネル一覧にも `l` がある。実装者はどちらかに寄せるが、ヘルプ（`?`）とステータスバーが片方だけになる。
- 修正案：`y` に統一し §4・§14 から `l` を消す（決定パネルは「—」のまま）。

### NA2. 「選定者」をどの案件設定項目で決めるかが無い
- シナリオ：S1, S3
- 何が起きるか：§1 の権限表は案件設定 PM 項目と購買項目を列挙するが、`選定者`（既定：設計）はどちらにも入っていない。誰が購買に変えられるのかが二通りに読める（PM 項目なら PM、購買項目なら購買）。選定のボールの持ち主を決める項目なので、ここが曖昧だと S3 で「私が選ぶの？」が起きうる。
- 修正案：`選定者` を PM 項目に入れ、変更は理由必須・影響試算なし（見積済未選定の行のボールが切り替わる旨を表示）。

### NA3. 最小ロット指摘の起票時期と「発注数」の存在
- シナリオ：S2
- 何が起きるか：§6.2 最小ロット（丸め）の R＝購買（発注数を丸める）、本文テンプレは「必要数 X → 発注数 Y」。しかし §3.2 で発注数は **選定確定時に自動設定** される。S2 のように概算段階で起票すると、購買は自分の指摘を自分で解決できない（発注数が無い）まま期限 2 営業日を超過し、PM が「止まっている」と見る。選定前は §8.1 の商社ごとの丸め数量・余剰がスコア内訳に出ているので、指摘は不要とも読める。
- 修正案：最小ロット指摘は **選定確定後のみ起票可**（選定前は `Shift+I` の `l` を灰色にし、ステータスバーに「選定前は内訳の余剰を参照」）。選定確定時に余剰が閾値超なら自動で `7`（最小ロットの閾値超）に載せ、購買の手起票を不要にする。

### NA4. 拮抗バッジの行を正式見積依頼に含めてよいか
- シナリオ：S3
- 何が起きるか：§2.1 で拮抗バッジの行は選定済でもボール＝選定者（見直し推奨）。§9.2 の `正式見積を依頼` が除外するのは「作業中●・承認待ち」だけで、拮抗行は含まれる。購買が依頼書を出した後に設計が選び直すと取下げ・再発行になる。購買は「拮抗行は待つべきか」を設計に聞く。
- 修正案：`正式見積を依頼` の実行時に「拮抗 15 行を含める / 除外する」を聞き、除外した行はボール＝選定者のまま。選定期限（2 営業日）を過ぎた拮抗バッジは自動で確認済み扱いにして依頼対象に入れる。

### NA5. 委譲された再選定（`p`）で例外閾値の PM 承認を再び要求するか
- シナリオ：S6
- 何が起きるか：§9.1 `p` で購買に委譲し理由「納期」が自動で付くが、§8.2 の規則では 1 位以外を選んで閾値超なら PM承認待ちになる。委譲した PM に再び承認が戻る（ループ）のか、委譲は閾値判定を免除するのかが読み分けられない。
- 修正案：委譲行は「納期NG 対策の再選定」として閾値判定を免除し、決定イベントに「委譲先の選定結果（商社・差額）」を記録。差額が上長決裁条件に該当する場合だけ PM に戻す。

### NA6. 変更セット起因の「再見積要」を購買が据え置き確定する操作
- シナリオ：S5
- 何が起きるか：§4 の再見積要は「購買が再依頼（見積中へ）または据え置き確定」で外れるが、据え置き確定のキーは「要再確認」（`5` で `1 据え置き / 2 再見積 / 3 提案値で確定`）と「指摘対応のとき」にしか書かれていない。変更セットで型式が変わった行に同じ `1`/`2` を使うのか、別操作なのかが二通りに読める。
- 修正案：§4 の再見積要の行に「`5` で商社ごとに `1 据え置き / 2 再見積`（要再確認と同じ操作）」と明記する。
