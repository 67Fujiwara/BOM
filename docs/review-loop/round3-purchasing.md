## 3. 新規 AMBIGUOUS（文面が二通りに読める箇所）

### NA3-01 購買の入力（単価・正式見積値・発注数）は即時反映か、`Ctrl+Enter` で公開か
- **シナリオ**：S3、S4
- **二通りの読み**：§5「`Ctrl+Enter` = 公開。役割に関係なく『自分の未公開の行＋自分の下書き指摘』をまとめて発行」を素直に読むと、購買の見積入力も作業中に積まれ公開まで設計に見えない。一方 §7 の取り込みは「商社列に流し込む」で即時に読める。前者なら購買が公開を忘れた行は見積済にならず、設計が「まだ入っていない」と聞きに来る。
- **修正案**：§5 に「作業中/公開済の分離は**設計列のみ**。購買列・PM の決定は即時反映。購買の `Ctrl+Enter` は下書き指摘の発行だけ」と明記（ステータスバー「未発行 12 件」と整合する）。

### NA3-02 見積・採用が無い段階（提出直後）の「要再確認」の外し方と、価格差判定
- **シナリオ**：S2（概算依頼前に型式あいまい 5 件・廃番 2 件を直す）
- **二通りの読み**：§4 要再確認は「指摘対応による型式/メーカ修正、置換、提案適用」で付き、外れる条件は「購買が `5` で商社ごとに `1`/`2`/`3`」だけ。商社列が1つも無い行では選ぶ対象が無く、`x` で外せるのか、自動で外れるのかが読めない。同じく §6.3「価格差 ＝ 提案単価 − 旧採用単価」は採用前の行では計算できず、`7` に載るのか載らないのかが読めない。
- **修正案**：「商社の見積が1件も無い行では要再確認を付けない（提出済のまま概算依頼に含める）」「旧採用単価が無いときは価格差判定をしない」を §4/§6.3 に追記。

### NA3-03 「要再確認」の括弧書き（型式あいまい・メーカ未記入）は例示か限定か
- **シナリオ**：S4（PM `d` → コスト超過 → 設計が同一行で型式を変更）、S5
- **二通りの読み**：§4 要再確認「指摘対応（型式あいまい・メーカ未記入）による型式/メーカの修正」。限定と読むと、コスト超過・数量見直し依頼・質問への対応で同一行の型式を変えたときは要再確認も再見積要（「変更セットで」が条件）も付かず、§5 で指摘対応は変更セットから分離されるため、どのフラグも立たない。正式依頼中以降は「取下げ・再発行対象」が拾うが、見積中・見積済・選定済の行は拾われない。
- **修正案**：「指摘対応による型式/メーカの修正（種別を問わず）」に書き換える。

### NA3-04 メーカ指定＝任意 かつ 代替可否＝不可 の行で、商社が埋めたメーカの扱い
- **シナリオ**：S1、S3
- **二通りの読み**：§3.1「任意の行は…購買が依頼 Excel の代替提案列でメーカを埋める」と §7「代替可否＝不可の行は（代替提案の指摘を）生成せず履歴のみ」が同時に成り立つと、この組合せの行はメーカが永久に埋まらない。「メーカ埋めは代替提案ではない」と読むなら生成されるが、どの種別の指摘になるかが書かれていない。
- **修正案**：§12 に「メーカ指定＝任意 かつ 代替可否＝不可 は矛盾（エラー）」を追加するか、取り込み時にメーカ指定＝任意の行の提案は種別「メーカ未記入」（提案欄にメーカのみ）として生成し、代替可否の判定対象外にする。

### NA3-05 例外閾値「¥10,000 かつ 3%」の「金額差」が単価差か行金額差か
- **シナリオ**：S3（2 位商社を選ぶ）
- **二通りの読み**：§8.2「金額差が例外閾値以内」。§8.1 で実質単価が定義されているので「実質単価差」とも「実質単価差 × 必要数」とも読める。どちらかで PM に上がるかどうかが変わる。
- **修正案**：「金額差 ＝ (実質単価_選択 − 実質単価_1位) × 必要数」と明記。差分超過（§9.2）の ¥10,000 も同じ定義であることを添える。

### NA3-06 指摘種別「納期NG」の R＝「購買 / 設計」ではボールが導出できない
- **シナリオ**：S6（購買が `Shift+I` → `n` で起票）
- **二通りの読み**：§2.1 は「種別の R が設計／購買」で分岐するが、§6.2 の納期NG は R が両方。フラグの納期NG（§4）は PM が対策区分を割り当てるので、指摘の納期NG が「PM に申告する入口」なのか「設計/購買のどちらかに直接頼む指摘」なのかが読めない。
- **修正案**：指摘種別の納期NG を「R＝PM（対策区分の割当）」にし、起票で §4 の納期NG フラグを立てる（起票者の本文は決定パネルに表示）。

### NA3-07 `Shift+I` の頭文字に「数量見直し依頼」「発注後変更依頼」が無い
- **シナリオ**：S5（発注済の行を設計が変えたい）、S2
- **二通りの読み**：§6.3 の頭文字は k/m/d/a/l/q/n/o。発注後変更依頼（§4 で設計が購買へ起票する前提）と数量見直し依頼（購買が直接頼みたいとき）は `o` その他で起票するしかなく、その他には §6.2 の R が無いのでボールが導出できない。「PM `q` 経由だけ」と読むか「その他で代用」と読むかで動きが変わる。
- **修正案**：頭文字に `c` 発注後変更依頼（設計のみ）、`v` 数量見直し依頼（購買のみ）を追加。「その他」は R＝相手役割（質問と同じ）と定義。

### NA3-08 先行発注許可後の「見積済 → 発注済」直接遷移は選定をスキップするのか
- **シナリオ**：S6、長納期品
- **二通りの読み**：§4「見積済・選定済 → 発注済 の直接遷移を許す」。見積済から直接なら商社が決まっていない行を発注することになり、購買は選定者に「どこに出す？」と聞くことになる。「正式見積をスキップするだけで選定は必要」とも読める（§8.2 の先行採用はそう読める）。
- **修正案**：「先行フラグは正式見積依頼をスキップする許可。発注は選定済（`a` / `Shift+A` / 先行採用）の行だけ」とし、遷移を「選定済 → 発注済」に限定。

### NA3-09 発注済の行が納期NG になったとき、決定パネルの `b`（次点へ）`p`（委譲）は有効か
- **シナリオ**：S6（入荷予定 > 必要日 の発注済行）
- **二通りの読み**：§9.1 納期NG の選択肢は b/p/d/e で一律。発注済の行で `b` を選ぶと既存の発注を取り消す必要があるが、発注取消の記録・遷移（発注済 → 選定済）は §4 に無い。「発注済でも b/p 可（取消は手動）」と「発注済は e と受入だけ」の両方に読める。
- **修正案**：発注済の行では決定パネルに `e` 特急・分納 / `s` 納期短縮交渉（購買）/ `Shift+Y` 受入 だけを出し、`b`/`p` は「発注取消を伴う（取消理由・取消日を記録、状態を選定済に戻す）」と明記した上で有効にする。
