## 2. 新しい不具合

形式：重大度 / 再現（キー列）/ 期待 / 実際 / 証跡 / 推定原因

### N12-01 ダイアログの文字欄をマウスでクリックしてから数字で始まる番号・補足を打つと、先頭の数字で理由が選び直され、その数字が欄から消える
- 重大度：**重大**（新人は「変更番号」の欄をクリックして打つ。公開の理由が黙って別の理由になり、変更番号の先頭の数字が消えたまま公開・履歴に残る。採用の理由も別の理由になり PM の判断材料が変わる。欄にカーソルがあるので、数字が選択肢に使われるとは思わない）
- 再現：
  - 公開：設計で R030 部品名を直す → `Ctrl+Enter` → `1`（客先要求）→ 変更番号の欄をクリック → `2 0 2 6 - 0 1 2` → `Enter`
  - 採用：R005 で `Alt+Shift+A` → `2`（2 位）→ 理由 `1`（納期）→ 補足の欄をクリック → `3`（打鍵）＋「日で入る」（IME）→ `Enter`
- 期待：欄をクリックした（フォーカスが欄にある）ら Tab と同じく文字の欄へ移ったとみなし、数字は欄に入る → {客先要求, "2026-012"}、「納期: 3日で入る」
- 実際：`2` で「設計起因」に選び直され、欄は「026-012」→ **changeSet {reason: "設計起因", changeNo: "026-012"}**、「行 6（Rev.2）を公開しました」。採用は **「実績/品質: 日で入る」**（`results/w01_dialog_digits.out`「欄をクリック」の 2 件、`shots/w01_click_changeno.png`、`shots/w01_adopt_click_3.png`）
- 推定原因：`src/commands/keyboard.ts:205`（数字で選ぶかどうかを `!panel.text && !panel.textTouched` だけで見る）。`textTouched` は Tab（`:554-556`）と欄の文字の変更（`src/ui/Panels.tsx:304`）でしか立たず、クリック・フォーカスでは立たない。キーは表の側で先に処理されるので、フォーカスが欄にあっても数字は選択肢に使われる

### N12-02 Tab で文字の欄へ移ったあと Shift+Tab で選択肢へ戻っても、数字で選び直せず、数字が番号・補足に入る
- 重大度：**中**（理由を間違えたと気づいて Shift+Tab で戻り数字を押すと、理由は最初のまま、番号の後ろに数字が付いて公開される。通知は「選び直しは数字か ↑↓」のまま）
