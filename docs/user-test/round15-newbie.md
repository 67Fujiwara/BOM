## 2. 新しい不具合

形式：重大度 / 再現（キー列）/ 期待 / 実際 / 証跡 / 推定原因

### N15-01 【悪化】見積書・購入品リスト風の見出し（品名｜規格｜メーカー｜単価｜数量｜金額）を見出しと見なさず、列を位置で決めるので **数量に単価（1200・3000・2500）** が入り、そのまま購買へ公開される
- 重大度：**重大**（新人の手元の「部品表」は見積書・購入品リストを流用したものが多い。エラーは見出しの行の「数量 0」1 件だけで、知らせのとおりその行を消すと、数量 1200 個・3000 個・2500 個、回路記号 4800・6000（金額）、分類 1・2・3（No）のまま Rev.1 で公開される。r14 のビルドでは見出しとして読み、部品名・メーカー・数量は正しかった）
- 再現：ガイド → `1`（貼り付け）→「No｜品名｜規格｜メーカー｜単価｜数量｜金額 / 1｜リレー｜MY4N-D2 DC24｜オムロン｜1200｜4｜4800 / 2｜タイマ｜H3CR-A8｜オムロン｜3000｜2｜6000 / 3｜ブレーカ｜NF32-SV 2P 10A｜三菱電機｜2500｜1｜2500」→ `Ctrl+Enter` → `Enter`（作成。カーソルは R001 の必要数）→ 1 行目が見出しの行なので `Shift+Delete` → `Ctrl+Enter`。xlsx（b1）・「品名｜仕様｜型式｜単価｜数量｜金額」（b2・e2）も同じ
- 期待：r14 と同じく 1 行目を見出しにする（品名 → 部品名・メーカー → メーカ・数量 → 数量。規格・単価・金額は使わない）。表題欄かどうか迷うときも、数量の列の中身が数（4・2・1）で見出しの語の下にそろっている表は見出しとみなす
- 実際：プレビューは「見出しなし」「1列目 → 分類 / 2列目 → 部品名 / 3列目 → 型式 / 4列目 → メーカ / 5列目 → 数量 / 6列目 → 単位 / 7列目 → 回路記号」。**{1｜4800｜リレー｜MY4N-D2 DC24｜オムロン｜1200 個}{2｜6000｜タイマ｜H3CR-A8｜オムロン｜3000 個}{3｜2500｜ブレーカ｜NF32-SV 2P 10A｜三菱電機｜2500 個} で「行 3（Rev.1）を公開しました」**、購買の 1 すべてに「リレー MY4N-D2 DC24 オムロン 1200 個」（`results/r07_estimate_follow.out` と `_r2.out`、`shots/r07_purch.png`、`shots/r02_e1_preview.png`、`results/r01_files15.out` b1・b2、`results/r02_paste15.out` e1・e2）。r14 のビルドでは map=[null,"name",null,"maker",null,"qtyNeeded",null] で 4 個・2 個・1 個（`results/r00_oldnew.out` の b1_estimate_cols・H5）
- 同じ原因：見出しの行の右端にページ番号（「頁｜1」）がある表（b3・e3）、号機の列が「1｜2｜3」の表（e4）も見出しなしになり、見出しの行が 0 個の部品の行・No が分類になる（r14 は正しく見出し）
- 推定原因：`src/io/paste.ts:155-160`（`3d82970` で追加した表題欄の判定 `alternating`：見出しの語のすぐ右がどれも見出しでない値なら表題欄とみなす。「品名→規格」「メーカー→単価」「数量→金額」が当たる。`numCell` は数だけのセル（「1」）が 1 つでもあれば表題欄とみなす）。`counts` を 0 にするので、ほかに見出しが無いと `best < 2` で見出しなしになる

### N15-02 【悪化】「変えた行だけ変更後を書く」変更図に追加の部品が 1 行でもあると、**変えていない部品が全部「削除」とみなされて BOM から消える**
- 重大度：**重大**（変更後の列を変えた行だけ書く変更図は、アプリ自身が r13 から読める書き方（V13-04）。そこに部品を 1 つ足すと、変えていない部品（タイマ・ブレーカ）が取り込まれず、2 行だけで Rev.1 公開される。消えた部品は購買の見積・発注に出ない。知らせは作成の知らせの先頭に出るが、「新しい版の列が空で前の版だけに値がある 2 行（例: タイマ H3CR-A8 オムロン）は、削除された部品として取り込みません」と言い切るので新人は削除だと思う）
