## 3. 使い勝手（不具合ではないが、ベテランが引っかかる点・確認できた良い点）

1. **同じ行の別の項目でも公開を戻さない**（C6）：A が R010 の部品名を公開 → B が R010 の**メーカ**を作業中に → A の Ctrl+Z は「戻せません…」。安全側で正しいが、部品名だけ戻してメーカの作業中は残す、もできる（`src/model/store.ts:255`、行ごとに `working` 全体を比べる）
2. **起動時の整え直しは画面だけ**：取引停止の商社を採用した R013 は、起動直後の画面は「見積済 · 正式依頼取下げ」なのに保存データは「正式見積済」のまま（次の操作まで保存しない。S0）。同じデータを開いた別のタブ・書き出した Excel と食い違う時間がある
3. **JSON の読み込みの「表です」の判定**：JSON の先頭に「// 書き出し 2026-10-23」の 1 行を足したタブの字下げの JSON は「これは表（タブ区切り・CSV）です」と言う（L11。r16 ビルドは「JSON として読めません」）。先頭に BOM（U+FEFF）の付いた JSON を貼ると「JSON として読めません」（L9、両ビルド。ファイルから選べば読める）
4. **2 ページ目だけ上の段がある変更表**（UP4：1 ページ目は「型式(旧)・型式(新)」の 1 段、2 ページ目は「部品名・旧・新」の 2 段）は、上の段が「部品名 / 新 / 0」の部品になり、2 ページ目の部品名が空（両ビルド）
5. **macOS の欄の中の Control+英字**（`111-mac-ctrl-mac-run1/2`・`114-mac-ctrl-typed-run1/2`）：編集中・パレット・絞り込みの Control+E・K・F・P は欄に任せる（ラウンド16 の修正どおり。`prevented: false`、編集中の値はそのまま）。表の上の Control+英字と、Linux の動き（`-linux`）はラウンド16 と差 0
6. **良い点（確認できたこと）**
    - ラウンド16 の重大 3 件はその形ではすべて直った：変えた行だけの 300 行（z1・p3）は 300 行、上の段の繰り返し 300 行（p1）は部品名が空 0、EDA の 300 行（z2・z2b・p4）は 300 行・数量の合計 1,494
