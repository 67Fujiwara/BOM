### M-01 上長決裁の入力（承認者・日付・決裁書 No.）が決定処理に渡らず、該当する承認・受入が一切できない
- 重大度：**致命**
- 再現：サンプル案件で設計 `Ctrl+G R047` → `Shift+A` → `2` → `Enter`（PM承認待ち）→ PM に切替 → `7` → `y` → 承認者「部長 田中」・決裁書No「K-1」・理由を入力 → `Enter`
- 期待：§9.1「上長決裁に該当する決定だけ、`y` の後に承認者・日付・決裁書 No. の入力が必須」。入れれば承認できる
- 実際：入力欄に値が入っていても毎回「上長決裁の条件に該当します。承認者を入れてください」で拒否され、ダイアログも閉じる。差分超過の受入（行の差額 ≥ ¥300,000）も同じ。サンプル案件は概算 ¥28M／予算 ¥2.8M で「予算比 +5%」に常に該当するため、**PM はサンプル案件で承認・受入を 1 件もできない**。同じ原因で決定パネル `e` の「上限金額」も記録されない（決定の payload が空）
- 証跡：`out/s3r.out`（`after y → 上長決裁の条件に該当します…`）、`out/s4r.out`（`受入(上長決裁) →` 同文）、`dbg_ext.mjs`（入力欄の値を読み戻したうえで拒否）、`out/s6r.out`（`e →` で `decision undefined`）
- 推定原因：`src/commands/keyboard.ts:153`（と `:144`）が `panel.onSubmit(choice, panel.text)` と 2 引数で呼び、`panel.extra` を渡していない。受け側 `src/commands/registry.ts:479-487` は第 3 引数 `extra` の `承認者`・`上限金額` を読む。`3 客先承認取得` の日付も同じ経路（既定値で代替されるので気付きにくい）

### M-02 「あとで（Shift+→）」にした問題が解除できず、案件を二度と公開できなくなる

## 3. 使い勝手

### U-01 6 商社別・8 正式見積で、Enter/Tab で確定したあと続けて数字を打てない
- 重大度：**中**
- 再現：購買 `6` → 単価セルで `Enter` → `1200` → `Tab` → `5`（次の納期を打つつもり）

- 推定原因：`src/commands/keyboard.ts`（数字キーを常にビュー切替に割り当て。単価・納期など数値列の上でも同じ）
