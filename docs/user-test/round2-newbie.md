## 2. 新しい不具合

形式：重大度 / 再現（キー列）/ 期待 / 実際 / 証跡 / 推定原因

### N2-01 パレットに操作名どおり「JSON を書き出す」と打って Enter すると「公開」が実行される（購買は「指摘」Enter で下書きが全件発行）
- 重大度：**重大**（社内の他役割への公開・発行が、意図と違う操作として起きる）
- 再現 A（設計）：`Ctrl+K` → `JSON を書き出す` → `Enter` → `Enter`
- 再現 B（購買）：`Shift+I` → `q` → 本文 → `Enter`（下書き 2 件作る）→ `Ctrl+K` → `指摘`（もう 1 件起票するつもり）→ `Enter`
- 期待：ラベルが完全一致・前方一致する「JSON を書き出す」「指摘を起票」が先頭。公開・発行は確認を挟む（flow-design §5「確認に `行 5 / 指摘 1 を公開` と出す」）
- 実際：A は先頭が「公開（提出 / 指摘を発行）」で、Enter → 「公開の Rev」→ Enter で **下書き 5 行が Rev.2 として購買に公開**、JSON はダウンロードされない。B は確認なしで「指摘 2 件 を公開しました」。他にも「案件を開く」「案件一覧」→ 先頭が「新しいBOM」、「納期」→「先行発注を申請」、「ログアウト」→「履歴」、「購買」→ 3 番目に「公開」。Ctrl+Z で戻せるが、新人は公開されたことに気づかない
- 証跡：`results/r15_extra.out`（`top 流れ公開…` → `行 5（Rev.2） を公開しました download none`）、`shots/r15_1440_json_export_published.png`、`results/r11_purchasing.out`（`palette 指摘 Enter … 指摘 2 件 を公開しました`）、`shots/r11_palette_shiteki_enter.png`、`results/r04_misc_old.out`（U-01 行）
- 推定原因：`src/commands/registry.ts:1375` のキーワード判定 `ql.includes(k)`（「JSON を書き出す」が公開のキーワード「出す」を、「ログアウト」が履歴の「ログ」を、「納期」が先行発注の「長納期」に部分一致）と、`registry.ts:1379-1384` が一致度で並べず最近使った順だけで、`STATIC`（`registry.ts:1265-`）の先頭にある publish が勝つ。さらに `registry.ts:462` は変更セット・追記の選択が無い場合（購買の指摘発行など）確認なしで `rows.publish` を実行する

### N2-02 セルを選んで英字で始まる値をいきなり打つと、先頭の 1 文字がコマンドとして実行され、残りの文字が値として入る（別の行が書き換わることもある）
- 重大度：**重大**（Excel の習慣で必ず起きる。置換行の作成・行の非表示・別の行の型式の上書きが、気づかないうちに起きる）

### 最重要 3 件
1. **N2-02** セルを選んで英字の値をいきなり打つと、先頭の文字がコマンドになる（`relay` で置換行ができる、`hello` で行が隠れる、`nut` で **別の行の型式が「ut」に書き換わる**）。Excel の習慣で新人がほぼ必ず踏む。
2. **N2-03** 編集中にサイドバーのビューをクリックすると、入力が **新しいビューの先頭行に書き込まれる**（N-25 の悪化）。あわせて N2-04（Ctrl+K・? ボタン等のクリックで入力が黙って消える）。
3. **N2-01** パレットに操作名どおり「JSON を書き出す」と打って Enter → Enter で **公開（Rev.2）** が走る。購買は「指摘」Enter で下書きが確認なしで全件発行。並びが一致度順でなく、キーワードの部分一致が逆向きにも効くため。
