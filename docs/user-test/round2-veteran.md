### V2-01 パレットに正式なコマンド名を打って Enter すると、別のコマンドが実行される（社外向けの依頼も走る）
- 重大度：**重大**（中堅 M-14 と同根。ベテランはパレットを名前で叩くので必ず踏む）
- 再現：購買で `Ctrl+K` →「見積回答を取り込む」→ `Enter`。同様に「正式見積を依頼（社外）」「商社を追加」「ルールを追加」「ショートカット一覧」「案件設定を確定（PM）」「この行だけ重みを変える」「承認 / 受入 / 許可（PM）」
- 期待：§9「すべての操作がコマンドパレットから名前で実行できる」。打った名前と一致する項目が先頭
- 実際：先頭は「見積回答を取り込む」→**概算見積を依頼**（購買なら回答期限を聞かれ Enter で商社 3 社分の依頼書を出して状態を見積中にする）、「正式見積を依頼（社外）」→**概算見積を依頼**、「商社を追加」「ルールを追加」→**行を追加**（設計なら行が増えて編集に入る）、「ショートカット一覧」→**受信箱**、「案件設定を確定（PM）」→案件設定、「承認 / 受入 / 許可（PM）」→役割を切り替え、「この行だけ重みを変える」→案件設定。keymap.ts の 72 ラベル中 21、パレット専用 30 名称中 11 で先頭が別。さらに最近使ったコマンドが名前一致より上に来るため、ガイドを一度使うと「案件設定」+Enter で**新しいBOM** が開く（`14-focus-storage.json`）。「推奨（最高スコア）で採用。見積済のみ」など句点を含むラベルは一覧に出ない（`。`を `.` に変換して照合するため）
- 証跡：`10-help.json`（palette.keymapNotFirst / staticNotFirst）、`dbg-vc.mjs` の出力
- 推定原因：`src/commands/registry.ts:1375` のキーワード照合 `ql.includes(k)` で「見積」「追加」「一覧」「pm」「重み」など短い語が長い問い合わせに当たる。`:1376` の keymap ラベル一致は STATIC の後ろに追加され、完全一致・前方一致の優先順位がない。`:1379-1384` の並べ替えが最近使った順だけを見る。`:1303` の `toHalf()` が `。` を `.` にしてラベル照合を外す

### V2-02 見積回答の取り込みが数値を検証せず NaN・負値・桁違いを保存する。依頼書を丸ごと貼ると全行の単価が NaN になる

- 再現：購買 → `Ctrl+K` 見積回答を取り込む → 商社を選び、`行ID 型式 単価 納期 MOQ` の見出しつきで `R030 / 1,200円 / 2週間 / 10個`、`R031 / １２００ / 14`、`R033 / -500 / -3 / 0`、`R034 / 1e9 / 99999` を貼って `Ctrl+Enter`。別に、ダウンロードした概算依頼書を商社が記入した想定で**シートを丸ごと**（表題・依頼No 行つき）貼る

- 証跡：`08b-io.mjs` の importNaN（memory / nanTexts / afterReload）、`08-io.json` import/wholeSheet・import/garbage

## 4. 使い勝手（不具合ではないが、ベテランが引っかかる・遅いと感じる点）

1. **反応時間**（V-t）：ビュー切替 1 回 130〜170ms、300 行で Space 0.66 秒。1〜9 を連打すると体感で引っかかる。`buildViewModel` を各コマンドが呼び直している（`registry.ts:27 vm()`、`moveCursorRow` ほか）ので、表示中のモデルの再利用で下がる見込み
2. **Excel の上書き入力の感覚とずれる**：ナビで文字を打つと上書き編集になるが、先頭が `a r o i h s f c n x w y j k` だと別の操作になる（「abc」→ 採用、「SJ-…」→ 降順並べ替え）。`Enter` は追記編集（F2 相当）なので、Excel の「Enter で下へ」の癖では値が後ろにつながる。設定で「Enter=下へ移動」を選べるとよい
3. **Alt+Enter で改行できない**（Excel 流）。入力は 1 行に連結される（`12-boundary.json` altEnter）
4. **1280 以下でヘッダーの金額（概算・正式・予算）が消える**、853（150%）ではランプ（設計待ち・エラー件数）も消える。1440 でも予算の % とランプが「…」で切れる
5. **一部のエラーが打ち終わってから出る**：発注済の行・置換済の行・役割外の列は、`Enter` の時点で分かるので入口で止めたい（V2-22）
6. **見出し行のない貼り付けの列順**：ガイドは見出しの言い換えを広く拾うが、見積回答の取り込みは「行ID」「単価」が 1 行目にある場合だけ見出しとして扱う（V2-02）。依頼書の形のまま戻ってくる前提にしてほしい
7. **Undo の粒度**：他タブ・他役割が同じ行の別の列を触っただけで自分の Undo が消える（V2-06）。列単位の判定と「戻せなかった操作は履歴に残す」がほしい
8. **2 タブ運用は概ね良好**：別の行・同じ行の別の列・交互 20 回・同時公開・役割のタブ別保持はすべて正しく合流した（`07-twotab.json`）。同じセルは後勝ちで、通知はない
9. **IME は問題なし**：isComposing / keyCode 229 / Process のどれでも 1 キー操作・Enter・Esc・Tab が誤作動しない。8 種の入力欄でも確定 Enter で送信されない（`09-ime.json`）
10. **出力の安全性は良好**：`=HYPERLINK(...)`・`+SUM`・`@cmd` は Excel に文字列として出て数式にならない。商社向け Excel に価格列なし。`<script>`/`<img onerror>` は画面でもコピーでも実行されない。JSON 往復（224KB）は完全一致
11. **ダーク / コンパクト / 150%**：カーソル枠（2px の inset）はどの組み合わせでも見え、全パネルが画面内に収まる。150% では表が 10 行（コンパクトで 13 行）しか見えない
