## 2. 新しい不具合

形式：重大度 / 再現 / 期待 / 実際 / 証跡 / 推定原因（file:line）。取り込みの不具合は直接呼んだ結果とガイドの .xlsx・.csv・.tsv が全形で一致（2 経路で再現）。「r21 ビルド」は 5198 と、その `src` を直接呼んだ `-r21b`。

### V22-01 区切りの決め方（列の数 × 行数）：コンマの数がタブの数以上の列があるタブ区切り（Excel のコピー・.xlsx・UTF-16「Unicode テキスト」・.tsv）が、コンマ区切りと読まれて全部の列がずれる【ラウンド21 の修正（V21-01）の副作用・退行】
- 重大度：**重大**（行数は合うので気づきにくい。部品名が「R11」、型式が「R12」、数量が読めず 0。知らせは「見出しが無いので、列を…と判断しました」「数量を読めない行が n 行あります」だけ。r21 ビルドは正しい）

- **削除の言い方の数え**：`232`（166 通り）。備考の列で「削除と読むべき」66 通りのうち削除 52・聞く 5・残る 9。「残すべき」72 通りのうち削除 17・聞く 13・残る 42。「聞くべき」28 通りのうち削除 0・聞く 17・残る 11。新型式の列では「削除と読むべき」66 通りのうち 30 通りが型式の文字になり、「残すべき」72 通りのうち 29 通りが削除になる
- **DNP の知らせ**：「実装しない部品（DNP・Not Fitted・未実装）の 5 行は取り込みません」は件数だけで、どの行かが出ない。備考の DNP は大日本印刷の手配メモのことがあるので、例の 1 行（先頭の 1 件）を出すとよい（削除の注記の知らせは「例: …」が付く）
- **「対応」の列の「不要」**：K05（追加／変更／不要）で「不要」の部品が「削除された部品」として外れる（知らせあり）。「対応」は状況の列としても使われるので、値が「不要」だけの行は【削除？】で聞くほうが安全
- **正しく囲んだ CSV は 100% 読む、を目標にするとよい**：`260` の RFC どおりの乱数を回帰試験にすると、V22-03 のような修正の副作用を早く捕まえられる（現行 17%、r21 ビルド 0%）
