# 利用者テスト ラウンド 3 — 修正対応表

対象レポート: [round3-mid.md](round3-mid.md)（中堅）、[round3-newbie.md](round3-newbie.md)（新人）、[round3-veteran.md](round3-veteran.md)（ベテラン）。ベテランのテストは中堅・新人の修正より前のコードで行ったため、重なる項目（V3-03・V3-06・V3-11・V3-13 の一部）はそちらの修正で解消。

確認: `npx tsc -p tsconfig.app.json --noEmit` 0 件 / vitest 24 件 合格 / Playwright E2E 14 件 合格（新規: リロード後の Undo・ビュー、取消が公開まで購買に見えない、anode / kit / knob / NEC / NJM2904 / DRV8833 の打ち始め）。

## 共通の原因（中堅 U-05・新人 N3-04）

`src/model/store.ts` で、保存キー（`bom-pro.ui` / `bom-pro.history`）の定数がストアを作る処理より後ろで宣言されていたため、初期化時の読み込みが例外になり、try/catch が握りつぶして既定値になっていた。ラウンド 2 で直したはずの「リロード後の Undo・ビュー・カーソル・ガイドの途中」（U-05・U-14・U2-09・N2-11）は、実際には効いていなかった。定数をストアの前に移し、E2E で確認する。

## 新人（N3 / U3）

| # | 内容 | 対応 |
| --- | --- | --- |
| N3-01 / N3-02 / N2-02 | Shift+英字・2 文字目が n/j/k・ゆっくり打つと、先頭がコマンドになる | 文字を打てるセルで英字コマンド（Shift 付きも）の直後 600ms 以内に文字が続いたら、コマンドを取り消して入力に。j/k/n どうしの連続とその後の数字だけはコマンドのまま。Shift キー単独の押下で判定が切れていたのも修正。`r`（置換）は先に新しい型式を聞くダイアログにして、ゆっくり打っても黙って行が作られない |
| N3-03 | 「採用」Enter で 70 行を確認なしに一括採用 | 一括採用は件数を見せて既定「やめる」で確認。「採用」は今の行の「推奨で採用」が先頭 |
| N3-05 / N3-12 | 表題行・表紙シートを部品として取り込む | 見出しの行を上から探し、上の行は理由つきで飛ばす。複数シートは見出しのあるシートを読み、シート名を知らせる |
| N3-06 | リッチテキスト・エラーのセルが [object Object] | セルの値を文字に（リッチテキスト・数式・リンク・日付、エラーは空） |
| N3-08 | 順番に直すモードの「編集する」が次へ進む | 編集の確定（Enter）を待ってから次の問題へ |
| N3-09 | 決定パネルで Enter 3 回で受入 | 既定の選択なし。キーか ↑↓ で選ぶ |
| N3-10 / U3-01 | 「直す」→ やり直す、言い換え不足 | 言い換えの完全一致をラベルの途中一致より先に。空白の有無を区別しない。エクスポート・案件を開く などを追加。新規・提出・採用・直す の先頭を単体テストで固定 |
| N3-11 | 8 に正式単価が 2 列 | 自動計算の列を外し、入力の列だけに |
| N3-13 | 回答期限の誤りでダイアログが閉じる | ダイアログを開いたまま理由を出す。「来週」「再来週」も読む |
| N3-14 | サンプルが再計算されていない | 作成時に整合させる |
| N3-15 | 見出しの素早いクリックで入力が消える | 押した時点で確定 |
| U2-02 | 一部のダイアログで Ctrl+K が効かない | どのダイアログでも、ダイアログ自身のキー処理より先にパレットを開く |
| U3-03 | 見出しなし 2・3 列のずれ | 左から 部品名・型式・メーカ（数字の列は数量） |
| U3-04 | 詳細の見出しが紛らわしい | スコア・価格点・納期点・実績点・条件点 |
| U3-05 | ビュー番号が薄い | 文字色を濃く |
| U3-07 | 貼り付け欄でもフッターが「Enter 次へ」 | 「Ctrl+Enter 次へ（Enter は改行）」 |
| U3-08 | 確認で「やめる」を選んでも何も出ない | 「やめました」と知らせる |

保留: U3-02（1 つずつ入力で最後の行の Enter で行を足す）、U3-06（編集できない列の英字はコマンドのまま＝仕様）。

## ベテラン（V3）
