### M4-01 置換（`r`・提案の適用）で作った行に、置換元との「回路記号の重複」警告が出て公開が止まる
- 重大度：**中**
- 再現：設計 `1` → 提出済の R060 で `r` → 新しい型式 `AB150-N` → Enter（R081 ができる）→ `Ctrl+Enter`。購買の代替提案を `Ctrl+.` →「購買の提案 … を適用して置換」でも同じ
- 期待：§6.3「置換 r / 提案を適用：元行は置換済、新行に置換元」。置換元は公開と同時に置換済になる行で、新行は同じ部品位置（同じ回路記号）を引き継ぐのが当然。M3-01 の修正で元行が公開まで有効のまま残るようになったが、それで重複扱いになるのは誤り
- 実際：「公開できません: 未確認の警告 1 件（R081 回路記号が他の行と重複しています … 直すか x で確認済みに）」。設計は置換のたびに新行で `x` を押す必要がある。`x` すると新行の重複チェックが確認済みとして残るので、後で本当に重複したときに警告されない
- 証跡：`out/w3.out`（`problems on new row [ 'warn:回路記号が他の行と重複しています' ]`、`publish try → 公開できません…R081 回路記号が他の行と重複`）、`out/v2.out`・`out/w4.out`（提案の適用でも同じ）
- 推定原因：`src/model/rules.ts:73-74` の重複判定が除外するのは取消・置換済の行だけで、置換・取消の作業中（`removal` / `pendingRemoval`）の行や、置換元（`replaces`）を除かない。`src/actions/rows.ts:313-327` の `replaceRow` は回路記号を含む設計列をコピーし、元行は `removal` を付けて有効のまま残す

### M4-02 PM が「対策不成立」を受け入れた（`Shift+Y`）後も、回答済の指摘が残って購買が発注できず、行が PM の 7 に残る

### M4-03 再見積要（型式変更）の行を購買が「据え置き（旧見積を有効に戻す）」にしても「提出済」のまま、選定できない

- そのほか、M4-01（置換のたびに重複警告で公開が止まる）は M3-01 の修正（置換元を公開まで有効のまま残す）の副作用で、毎回の置換に `x` が要るうえ、`x` が後の本当の重複を隠す。M4-06 / M4-07 と M3-11 の残りは「指定先」をどこで決めるか（客先指定品の指定先の保持、指定商社のマスタ照合、商社向け Excel の絞り込み）を 1 か所にまとめれば同時に直る
