## 2. 新しい不具合

形式：重大度 / 再現（キー列）/ 期待 / 実際 / 証跡 / 推定原因

### N7-01 打てないセルの通知「例: Alt+○」が打った文字をそのまま Alt に付けるため、Shift 付きの操作を押した新人が別の操作を実行する（購買が指摘のつもりで入荷済、PM が却下のつもりで承認、設計が商社を選ぶつもりで推奨採用）
- 重大度：**重大**（アプリの案内どおりに押しただけで、入荷済・承認・採用というデータの変更が起きる）
- 再現：
  - A（購買）：ビュー 1、`Ctrl+G R013` → 部品名（設計の列）→ 指摘を出すつもりで `Shift+I` → 通知「権限なし（設計の列）。1 キー操作は Alt を押しながら（**例: Alt+i**）か、ID の列で」→ そのとおり `Alt+i`
  - B（PM、承認 ON の変更セット）：7 の R033 部品名 → 却下のつもりで `Shift+Y` → 通知「…（**例: Alt+y**）…」→ `Alt+y` → ダイアログ「決定: 承認（R033・Rev.3 の変更セット 2 行まとめて。理由・任意）」→ 新人の癖で `Enter`
  - C（設計）：R005 スコア（自動計算）→ 商社を選ぶつもりで `Shift+A` →「…（例: Alt+a）…」→ `Alt+a`
  - D（設計）：R016 単価 → 指摘に返信のつもりで `Shift+R` →「例: Alt+r」→ `Alt+r` → 置き換え品のダイアログ。金額で `Shift+S`（降順）→「例: Alt+s」→ 昇順
  - E：単価で「ok」→「例: Alt+k」（前の行へ移動）、「sale」→「例: Alt+e」（割り当てなし）
- 期待：例は「その列で使える代表的な操作」（Alt+x・Alt+Shift+I など）か、押した操作に Shift があれば Alt+Shift+○ を示す。少なくとも押したキーと違う操作を案内しない
- 実際：
  - A：**「R013: 入荷済にしました」— 正式見積済 → 入荷済＋発注済**（発注していないのに入荷まで進む）
  - B：**「R033・Rev.3 の変更セット 2 行まとめて: 承認」**、決定 D-002 kind=承認、R033 型式が M2BJ-B24D-NEW に確定
  - C：**「R005 を ミスミ で採用（スコア 83.8 / 実績なし）」**（見積済 → 選定済）
  - D：置き換え品のダイアログが開く／昇順に並ぶ
  - 見積中の行（R076）で A をすると「入荷にできません（発注前の行）…」で止まる
- 証跡：`results/t50_toast_hint.out` A・B、`results/t51_shift_hint.out` B〜D、`results/t52_pm_shift_y.out`、`shots/t50_A_alt_i.png`、`shots/t52_alt_y.png`
- 推定原因：`src/commands/keyboard.ts:590` の `` `例: Alt+${ch.toLowerCase()}` ``。`e.key` を小文字にするので Shift が落ち、Shift+I（指摘）→ i（入荷）、Shift+Y（却下）→ y（承認）、Shift+A（商社を選ぶ）→ a（推奨採用）、Shift+R（返信）→ r（置換）に化ける

### N7-02 数字でビューを変えようとすると、部品名・型式などに数字が入り部品名が消える。サイドとヘルプは今も素の数字（「4 要確認」）を教える
